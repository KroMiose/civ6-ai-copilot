# 面向 AI 决策的数据路线图

状态：首批数据范围已按 D020 确认并纳入 0.3 contract、Skill 与 Mod 实现。首批 API 的真实对局验证仍待完成；下表中的次批和后续项目是路线建议，不属于当前已确认范围。

## 核心需求

副官应让玩家少解释局势、少切换面板，并获得符合当前规则、当前资源和当前可执行条件的回合建议。衡量标准是建议是否有依据、能否执行、能否解释取舍。

每项决策需要五类输入：

1. 现状：我有什么，位置在哪里，状态如何。
2. 选项：此刻有哪些可选行动，哪些条件未满足。
3. 代价与效果：金币、生产、维护、资源、时间及可确认收益。
4. 时机：当前紧急事项、下一次解锁、即将结束的效果或交易。
5. 目标：玩家想达成什么、接受什么风险，以及当前规则集允许什么。

0.3 首批已补当前选择、城市设施/生产/粮食、己方单位状态、总督、商路和已遇见城邦。候选行动、动态费用、时机窗口和方案比较仍需后续独立确认；玩家目标必须来自对话，不能从游戏状态直接推断。

## 当前缺口与优先级

“有 UI 依据”只指找到原生界面读取路径，不表示跨平台兼容、调用参数与多人可见性已全部确认。

| 优先级 | 数据 | 能改善的决定 | 当前情况与实施边界 |
| --- | --- | --- | --- |
| 首批（0.3 已实现） | 当前选中的己方城市/单位 | 理解“这座城造什么”“这个兵怎么走” | 导出己方 entity ID 和 selected/none/unsupported/error；每次刷新重采，不改变选择。实机 API 状态仍待核对 |
| 首批（0.3 已实现） | 城市已建区域/建筑、人口限制区域容量、当前生产进度/成本 | 区分缺基础设施、人口卡槽、即将完工与沉没成本 | 仅己方城市；区域可标记已建/在建，字段缺失仍表示未知 |
| 首批（0.3 已实现） | 粮食存量/盈余、增长阈值、围城状态 | 增长、住房、宜居度、修复与防守的优先级 | 保留已有六维产出、住房、宜居度与增长/饥荒回合；字段未提供时不补造 |
| 首批（0.3 已实现） | 工人剩余次数、己方射程/最大移动力、经验/晋升、升级费用 | 判断可用状态并解释升级成本 | 仅己方单位；升级费用不等价于可升级许可，移动力不等价于能攻击/建城 |
| 首批（0.3 已实现） | 总督、可用头衔、任命/驻扎/就职/晋升状态 | 任命、晋升、派驻、就职窗口 | 按当前可见规则读取；DLC 不适用和 API 不可用分别表示，不新增专题按钮 |
| 首批（0.3 已实现） | 商路已用/容量、涉及己方的现有路线 | 发现空闲产能，解释现有路线期限 | 只导出本方及 UI 可见的已遇见目的地字段；候选路线比较仍待验证 |
| 首批（0.3 已实现） | 已遇见城邦、己方使者、可见任务和公开宗主奖励 | 使者分配、顺路完成任务、关键宗主争夺 | 未遇见城邦和其他玩家私人使者不导出；不适用、不可用与已知空集合分开 |
| 次批 | 可生产/可购买选项及动态费用、禁用原因、真实生产队列 | 比较买、造、升级；避免推荐当前不可用对象 | ProductionPanel 存在成本和 CanStart 查询；参数、队列接口和只读性须单独验证 |
| 次批 | 科技/市政解锁结果、可见 boost 条件、剩余回合 | 把研究与军队升级、区域、政策窗口连接起来 | 已有项目、进度/成本、可选列表及 boost 布尔值。补规则说明；不猜隐藏 boost 计数 |
| 次批 | 时代分/门槛/界面显示的结束范围、己方忠诚度/转化倒计时 | 避免错过时代窗口，识别新城或占领城风险 | 原生 EraProgressPanel/LoyaltySupport 有依据；只导出界面已有精度，不能提前读取未来时代结果 |
| 次批 | 战略资源收入/消耗/预留、维护细分、己方交易期限 | 判断军队扩张、升级与资源耗尽风险 | 已有库存、总维护、净金币。Expansion2 ReportScreen 有资源流量依据；不能将分项相加当成已验证净变化 |
| 次批 | 当前可见外方城市的公开城防、城墙/驻军血量 | 判断是否具备攻城条件 | 当前缺独立观测记录；CityBannerManager 有读取依据，仍需逐字段可见性审计。与己方城市运营模块分离 |
| 后续按意图 | 宗教/信条、伟人点与进度、旅游/巨作、己方胜利项目、电力、自己的间谍任务等 | 支持特定胜利路线和中后期决策 | 本轮未逐项确认 API；先补玩家实际使用的系统，不能按全局玩家对象遍历获取隐藏竞争信息 |

当前自身文明/领袖、规则集、速度已有标识，但 AI 仍可能套用错误版本规则。建议补实际启用的规则/模式和相关能力说明；具体发现 API 待验证。玩家追求何种胜利、是否想打仗等由桌面侧保存明确偏好，与游戏事实分开。

## 最值得增加的是决策上下文

### 合法选项与原因

“城市正在造建筑”不能回答“下一步该造什么”。需要同城的可选生产、当前费用、购买费用，以及缺资源、缺前置、缺容量等 UI 已解释的限制。

先支持玩家选中的己方城市，以及无生产/即将完工的城市。避免每次刷新计算所有城市 × 所有对象 × 所有地块组合。只有证实安全的原生只读查询才接入；未知许可保持未知。不得为了查询而切换城市、创建交易、发起命令或调用 UI 初始化函数。

对攻击、移动、区域选址和商路也应用同一原则。完整寻路、战斗预览与相邻加成计算成本高，且有读取隐藏状态的风险，排在只读基础事实之后。目标只限玩家已知且允许评估的范围；不输出穿过未知区域的完整路径或“安全无敌军”结论。

### 真实待办与时机

先由已验证事实生成 `decisionSignals`（拟议名称），保持“派生提醒”与“游戏通知”两种来源独立。示例：无生产、饥荒倒计时、未使用总督头衔、闲置商路容量、可分配使者、当前研究待选、重伤且可晋升的己方单位。

仅以事实充分的规则触发。没有晋升许可就只提示重伤，不推断可晋升；有商路空位但无闲置商人时，不能说可立即建立路线。

真实通知 collector 后续可独立加入，仅读取本地玩家仍有效的通知，不调用选择、激活、已读、清除或派发行为。此前删除的 notifications 声明不能以派生提醒冒名恢复。

每条派生提醒应保留：对象引用、证据字段、采集时间、明确的截止回合或估算范围、严重度、推断方法与缺失前提。排序按紧急程度、截止时间、用户当前意图，再用稳定 ID 打破同级，避免数组顺序决定重点。

### 比较方案与解释取舍

桌面 TypeScript 先组织候选方案的已知代价，AI 再按玩家目标判断。例如比较某单位购买、生产、升级时，同时提供可行性、金币、战略资源、生产占用、完成时间和维护；没有合法 API 支持的数值不计算成确定结果。

政策、总督、科技解锁和特色能力使用运行时相关条目的名称、描述与 identifier，按引用去重。不导出整套 GameInfo，不打包 Firaxis 数据库，也不假设所有规则都能从描述文字精确算出。

静态说明可按本次规则环境缓存；费用、合法性和收益受城市/政策/回合影响，不能沿用为静态缓存。当前激活的政策、文明特性、总督状态用于说明建议依据，避免靠模型记忆补 DLC/Mod 规则。

## 地图数据应围绕行动组织

关键实体与地形采样分别设预算。己方单位/城市及当前可见威胁不能仅因地形 tile 名额用完而被默默遗漏。0.2 的外方单位发现仍依附入选 tile，需要继续改进；未采到不能解释成没有。

围绕以下局部问题提供事实集合：己方前线、开拓者附近、需要改良的城市工作圈、区域候选位置、沿海连接与探索边界。相关采样策略由桌面意图和安全的 Mod 默认策略决定，避免新增一排玩家按钮。

历史记忆需单独存储真实观测时间。迷雾中的历史地形可供路线讨论，但必须区别于当前事实；不可从当前 Plot 补“记忆”。外方单位消失可能是进入迷雾或采样遗漏，不能自动记为阵亡。跨载入关联未解决前，趋势仅限本次载入 session。

## 数据质量与 AI 使用方式

1. 模块存在不等于功能可用。明确区分成功且为空、不适用当前规则、API 不支持、采集失败，以及截断/部分覆盖。API 失败不能伪装成“没有商路/没有单位/没有政策”。
2. 保留每模块时间、来源、覆盖范围和必要的字段可用性；派生事实保留输入引用。不同采集时间组合时明确假设，不给伪精确的本回合操作链。
3. 桌面侧输出有界摘要：立即处理、近期窗口、影响当前目标的资源约束。完整合法数据留在本地，需要时按实体读取；未进摘要不等于未采集。
4. 摘要必须能说明缺口。地图截断、战争数据陈旧、费用未知等应直接约束建议的强度。信息足够的部分可以先分析，缺少关键依据的具体行动再要求更新。
5. 用户目标与游戏事实分离：偏好的胜利路线、近期计划、风险偏好保存于对话/本地分析记录，不写入游戏，不冒称 API 事实。
6. 对已接受计划做回合对照：目标是否仍可行、哪些前提改变。单位和城市减少只能先记“本次记录中缺失”，核对观测范围和事件后再判断损失。

## 建议实施节奏与验收

第一批：统一玩家入口，补己方城市/单位的高价值只读字段、选择上下文、总督、商路容量/现有路线、使者与已遇见城邦。每个 collector 独立提交与验证，不一次改完所有系统。

第二批：可行行动与动态费用、科技解锁/boost 条件、忠诚度/时代窗口，再加入基于证据的待办和方案比较。

第三批：按意图展开的地图详情、采样之外的关键实体覆盖、历史观测与趋势；随后按玩家需求接入宗教/文化/伟人/胜利/间谍等系统。

验收以具体问题为单位：城市下一步能造什么且为什么；商路有无空位且有无可用商人；总督是否有未用头衔；某单位能否升级且代价多少；哪些选择受资源/前置/时间限制。用合成 fixtures 验证事实缺失时拒绝伪造、已知时给出完整比较输入，再对照真实 UI。

性能记录采集耗时、UI update 最大耗时、API 调用量、wire 字节与摘要 token 大小。覆盖早期/后期、Huge 地图、DLC/Mod/平台差异。多人测试独立核对未遇见、迷雾、隐身单位、外方私人状态和目标查询侧信道；只读验证禁止命令、操作、选择和通知状态写入。
